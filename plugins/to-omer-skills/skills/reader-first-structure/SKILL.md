# 短文をつないだ階層箇条書きで説明する

- 本文は、短文の階層箇条書きを基本にする
  - 要点は浅い階層に、理由・具体例・補足は説明する対象の下に置く
  - 理由や推論も短文でつなぎ、順に読めば説明をたどれる形にする
- 一項目は短くするが、必要な説明は減らさない
  - 長い説明は、問いごとのまとまりに分けて残す
  - 文を断片にしたり、長い段落に箇条書き記号を付けるだけで済ませたりしない

## 1. 残す内容と置き場所を決める

- 読者の問いと、依頼された詳しさ・編集範囲を基準にする
  - 構成変更を、情報を削る許可とみなさない
  - 対象・事実・条件・確信度・発言者を保ち、資料にない理由や具体例を足さない
  - 架空の例か、実際の報告かという区別も保つ
- その箇所の理解に必要な答え・前提・理由・具体例は、その場に残す
  - 結論を変える条件・例外・不確実性も、関係する説明と一緒に示す
- 長い箇所は、分割する前に内容と配置を見直す
  - 後で必要になる情報は、その説明の近くへ移す
  - 独立して参照する証明や追加例は、案内を残して補足や付録へ移せる
  - 本筋の理解に必要な説明は残し、参照先との往復を前提にしない
  - 削除が許されている場合は、読者の目的に役立たない情報を省く
- 役割のない反復は統合する
  - 解説と早見表など、異なる読み方に役立つ再掲は残せる

## 2. 前提から理解できる順に並べる

- 読者が理解できる答えなら、先に示してよい
  - 新しい概念なら、理解できる問いや設定から始める
  - 具体例が必要なら、そこで何を調べたいかにつなげる
  - 要点を浅く置くことと、前提より先に置くことを分ける
- 読者にとって新しい用語・記号は、必要な説明とともに使う
  - 何のための概念か分かりにくい場合は、必要になる場面を示す
  - 初めて使う箇所で短く説明できるなら、そこで説明してよい
  - 読者が既に知っている用語まで、毎回定義し直さない
  - 未知の概念は、別の未知の概念との違いだけで説明しない
- 比較や計算は、対象・初期状態・使う規則を示してから進める
  - 比較では、共通の設定と変える箇所を区別する
  - 後の結果から、設定や比較対象を逆算させない
- 推論は、どの前提から何を得たかを追える形にする
  - 複数の前提から得る結論は、前提を並べた後か、それらをまとめる親項目に置く
  - 最後の前提だけの子項目にせず、必要な途中の操作も言葉や式で示す

## 3. 読む単位に合わせて項目を作る

- 問いごとに要点と説明をまとめてから、項目に分ける
  - 元の文や改行を、そのまま項目の区切りにしない
- 一項目には、一つの要点を短く書く
  - 主張・操作・理由は、助詞・述語・必要な接続を残した文にする
  - 主体や対象が切り替わるなら明示する
  - 分類や場合分けは、短いラベルで示せる
  - ラベルだけで、何がなぜ起こるかの説明を済ませない
- 別々に確認したい操作・条件・例が混ざるなら分ける
  - 短い条件と動作など、一緒に読んだ方が分かるものは一項目にまとめる
  - 分割で同じ条件の反復や文の断片が増える場合も、まとめ直す
- 必要なら、一項目に複数文を残せる
  - 一続きの推論など、分けるとかえって読みにくい箇所は短い地の文でつなぐ
  - 別の話題や長い説明全体まで、一項目に詰め込まない
  - 文字数や画面の折り返し位置だけでは区切らない
- 内容に合う形式を使い分ける
  - 同じ観点での比較は、表にまとめられる。必要な理由や条件は近くで説明する
  - 引用・語り・コード・数式など、まとまりが必要な内容は無理に分割しない
  - 一、二文で済む短い応答は、そのままでよい

## 4. 親子関係と条件の範囲を確かめる

- 子項目は、説明する対象の直下に置く
  - 理由・具体例・操作の効果が、親の何を説明するかを確かめる
  - 親が複数の動作を含むなら、どの動作についての説明か分かるようにする
  - 親の範囲から外れる話題は、その並びから外して別の項目や節に置く
- 関係は、親と子を合わせて読めば分かるようにする
  - 親の「次の二条件」や、子の「〜ため」「例えば」で分かれば、ラベルを重ねない
  - 役割を読み違えそうな箇所だけ、「目的：」などを添える
  - ラベルのためだけに一段増やさず、置き場所の誤りは名前だけで直そうとしない
- 子に何を並べるかは、親が示した問いと範囲で決める
  - 「二つの選択肢」の下には、その二つを置く
  - 一つの主張の下に理由と例を置く場合は、役割の違いが分かればよい
- 親項目の働きに合わせて、条件の示し方を決める
  - 主張には「平均」「一部」「未確認」など、成立する範囲や条件を残す
  - 「変更の条件」などのラベルは、何の説明を読めるか示せればよい
- 共通条件は、関係するすべての項目に掛かる位置に置く
  - 親項目や見出しから範囲が分かれば、子項目ごとに繰り返さなくてよい
  - 長い条件を分けるなら、「次の二条件を両方」のように組み合わせ方を示す
  - 離れた項目の条件を、説明なしで引き継がせない
  - 危険を避けるための注意は、該当する操作より前に置く
- 次の工程と、一工程の内訳・効果を区別する
  - 独立した工程は、同じ階層の番号で順に示す
  - 一工程の内訳は、その工程の下に置ける
  - 操作に伴う変化は、同じ項目か、その子項目に書ける
- 関係を言い直しても、元の意味を変えない
  - 根拠・原因・例を取り違えず、資料にない因果関係を足さない
  - 「すべて」「一つでも」が数える対象と、「ない」が否定する範囲を確かめる

## 5. 見出しと階層を整える

- 見出しには、その場所で読める対象や問いを書く
  - 題名は主題と範囲、下位見出しはその中の具体的な話題を示す
  - 見出しの階層は話題の包含関係で決め、結論・理由などの役割に固定しない
  - 見出し直後の要点文を必須にせず、見出し・導入・親項目の重複を避ける
- 同じ階層に五項目ほど続いたら、話題が混ざっていないか見直す
  - 五項目は上限ではなく、見直しの目安である
  - 空行やリストの区切りをまたいでも、一続きの説明として見る
  - 少数でも範囲がずれれば直し、明確な並列なら五項目以上でも残す
- 読み分けるために必要な深さは使う
  - 浅くするために、意味のある親子関係までなくさない
  - 同義ラベルの繰り返しや、一文を完成させるだけの階層は減らす
  - 長い独立した説明は、小見出しなどで区切り直せる

## 6. 表現を整えて読み直す

- 新規作成は常体を基本とし、既存原稿の文体と明示された指定を優先する
  - 動詞で終わる文・「である」・短いラベルを、内容に合わせて使う
  - 箇条書き末尾の句点は省き、複数文の途中の句点は残す
  - 引用・コード・数式の内部は、機械的に変えない
- 見出しと浅い項目を読む
  - 必要な説明を見つけられ、主張の条件を取り違えないか
- 親項目と、その子項目を合わせて読む
  - 何について、どの関係で説明しているかが分かるか
  - 不要なラベルや階層をたどらせていないか
- 全文を順に読む
  - 想定読者が、説明されていない前提を推測せずに、例や推論を追えるか
  - 元の資料の意味と一致し、本文・表・見出し・参照先が対応しているか

成果物には、依頼された本文と必要な出典を載せる。作業記録や自己評価は、求められた場合だけ別に示す。
