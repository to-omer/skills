# 短文の箇条書きを階層に分けて書く

- 本文は、短文を使った階層的な箇条書きを基本にする。
  - 要点は浅い階層に置く。
  - 理由・具体例・補足は、説明の対象となる項目の下に置く。
- 読者が、必要な箇所だけ詳しく読める形にする。
  - 子項目を読み飛ばしても、親項目の意味を取り違えない。
  - 全文を読めば、根拠と論理のつながりを追える。
- 長い段落に箇条書き記号を付けるだけでは済ませない。
  - 一文に含まれる要点と、それを詳しく説明する部分を分ける。
  - 推敲後も、要点と詳しい説明を選んで読める形を保つ。

## 基本形

架空の選定例：

```markdown
- 共同編集をしない用途では、A案を採用する。
  - 必要な保存機能を備えている。
  - 今回は追加費用がかからない。
    - 現在の契約に含まれている。
- 共同編集が必要なら、B案を選ぶ。
  - A案は共同編集に対応していない。
  - B案は共同編集に対応している。
```

- 親項目には、結論・判断・行動などの要点を書く。
  - 子項目には、その要点を詳しく知るための情報を書く。
- 「結論」「理由」などのラベルは、必要な場合に使う。
  - ラベルを重ねるより、要点を直接書く。
  - 毎回「結論・理由・補足」の形にそろえない。

## 何を残すか

- まず、読者が知りたいことを押さえる。
  - 明示された問いと、必要な詳しさを基準にする。
  - 理由の説明を求められたら、理由を中心に書く。
- 読者が目的を達成するのに役立つ情報を残す。
  - 問いへの答え
  - 答えを理解するための前提や推論
  - 判断を支える根拠、反証、不確実性
  - 正しく行動するための条件や注意
  - 分かりにくい点の理解を助ける具体例
- 読者の役に立たない情報は加えない。
  - 内容のない予告、同じ結論の繰り返し、本題から外れた一般論
  - 理解や判断に使わない仮定の列挙
  - 読者に関係しない作業報告や自己評価
- 原文がある場合は、編集を許された範囲を守る。
  - 箇条書きへの変換を、要約の許可とみなさない。
  - 意味を変えずに統合できる重複は整理する。
  - 事実・条件・確信度・発言者を勝手に変えない。
  - 架空の例か、実際の報告かという区別も保つ。
  - 説明を補うために、理由や具体例を勝手に作らない。

## 一項目を短くする

- 一項目には、原則として一文・一つの要点を書く。
  - 見出しに当たる項目や、ラベルと値は短く示してよい。
  - 別々に読める判断や操作は分ける。
  - 短い条件や因果関係は、一項目で無理なく読めるならまとめて書く。
- 本文の一文は、40字程度までを目安にする。
  - もっと短く自然に書けるなら短くする。
  - 文字数に合わせるために、条件や意味を削らない。
  - 画面の折り返しに合わせた強制改行はしない。
  - 固有名・引用・分けると意味が変わる条件は無理に切らない。
- 長い一文は、内容の役割ごとに分けて項目にする。
  - 主な判断は親項目に書く。
  - その理由や具体的な説明は子項目に書く。
  - 別の判断は、同じ階層の隣の項目に書く。
- 短くしても、文として意味が通じるようにする。
  - 主語や対象が切り替わるなら明示する。
  - 「Aは」「Bなので」だけの項目に切らない。
  - 助詞を落とした名詞の羅列にしない。
- 項目の冒頭から、何の話か分かるようにする。
  - 期限、対象、結論、行動を前へ出す。
  - 離れた項目を読まないと分からない指示語は言い直す。

## 親子関係を決める

- 一段深い階層に置くときは、親項目との関係を確かめる。
  - 「なぜ」「具体的には」「例えば」に答えるなら子項目にする。
  - 同じ問いへの別の答えなら、同じ階層に置く。
- 根拠、具体例、反論を、区別できるように書く。
  - 必要な箇所だけ「理由」「例」「ただし」を添える。
  - インデントだけで、関係を推測させない。
- 複数の前提から導く結論は、最後の前提だけの下に置かない。
  - 結論の下に、必要な前提をまとめる。
  - または、前提を並べてから結論を書く。
- 同じ階層に並べる項目は、対象の種類と説明の詳しさをそろえる。
  - 複数の案を並べた階層に、一案だけの欠点を混ぜない。
  - 文字数や子項目数を、見た目のためにそろえない。
  - 共通点が一つあるだけで、全体を同じと断定しない。
- 時間の経過や手順の順序を、階層を深くすることで表さない。
  - 順に行う手順は、同じ階層の番号付きリストにする。
  - 各手順の理由や確認結果だけを、その下へ置く。
- 深さは、まず2〜3階層を目安にする。
  - 4階層以上続く箇所は、不要なラベルや異なる話題の混在を見直す。
  - 長く続く説明は、内容が分かる小見出しを付けて分ける。
  - 浅くするために、意味のある親子関係までなくさない。
  - 子項目が一つでも、理由を分けて示す意味があれば残す。

### 条件と限定の掛かる範囲を保つ

- 親項目だけでも、何についてどこまで言えるか分かる形にする。
  - 「平均」「一部」「未確認」などの限定を子項目だけへ移さない。
  - 「無料」とだけ書き、適用期限を子項目だけに書かない。
- 何を数え、何を否定しているかを変えない。
  - 分類をまとめても、数える単位を変えない。
  - 特定の方法への否定を、対象全体への否定に広げない。
- 共通の条件は、関係するすべての操作や項目に掛かることが分かるように書く。
  - 短い一連の操作なら、条件とともに一項目にまとめる。
  - 分けるなら、共通の見出しか各項目に条件を示す。
  - 全体に掛かる限定を、一つの項目だけへ移さない。
- 条件が長い場合は、どこで確認できるかを親項目に書く。
  - 「次の2条件を両方満たす場合に利用できる」と書く。
  - 子項目には、条件を一つずつ並べる。
  - 「両方」と「どちらか」を省かない。
- 重要な例外や禁止は、補足の深い階層だけに書かない。
  - 該当する判断・操作の箇所で示す。
  - 危険を避けるための注意は、操作より前に置く。
- 情報の正しさや確実さを、階層の深さで表さない。
  - 深い階層の情報でも、判断を覆す内容は要点に反映する。

## 説明する順序を整える

- 冒頭に、読者が理解できる答えや問題を置く。
  - 答えに未説明の用語を使うなら、先にその役割を短く説明する。
  - 概念の詳しい説明は、必要になる箇所に置く。
- 一つの項目とその下の説明では、一つの問いを扱う。
  - 理由を読んでいる途中へ、別の用件を挟まない。
  - 同じ問いへの答えを、離れた箇所に分散させない。
- 短文化しても、論理のつながりを残す。
  - 因果・対比・条件は、必要な接続語で示す。
  - 番号や結論だけでなく、使った前提や途中の操作も説明する。
  - 説明が必要な式変形は、前後の式から分かる操作を言葉でも示す。
  - 「→」は、前後の関係が明らかな場合だけ使う。
  - 相関を因果関係とみなすなど、記号で元にない関係を示さない。
- 上から順に読んでも、自然につながるようにする。
  - 拾い読みを優先して、全文を読んだときの理解を妨げない。

## 地の文などを使う場合

- 基本は、短文を使った階層的な箇条書きで説明する。
  - 理由や因果があるだけで、地の文へ戻さない。
- 分けるとかえって読みにくい箇所は、短い地の文でまとめる。
  - 項目を読むたびに、直前の文を確かめる必要がある説明
  - 分けると同じ条件を何度も繰り返すことになる論証
  - 文の順序や間合い自体に意味がある語りや対話
- 地の文は、一続きの説明に必要な範囲にとどめる。
  - 理解のために必要なら、箇条書きの項目内に置ける。
  - 別の判断や補足まで、同じ段落にまとめない。
- 引用やコードは、そのまま読めるまとまりで置く。
  - 箇条書きにするために内部を分割しない。
- 複数の案を同じ観点で並べて比べるなら、表を使える。
  - セルが長文になるなら、案ごとの箇条書きに戻す。
- 一、二文で用件が済む返答は、そのままでよい。
  - 用件を伝えるのに不要な「結論」「補足」を付け足さない。

## 仕上げ

- 浅い階層の要点だけを読む。
  - ラベルだけの項目では、その直下の要点まで読む。
  - 答えと、判断を変える条件が分かるか。
- 一つの項目とその下の説明を、親項目と一緒に読む。
  - 何を説明しているか分かるか。
  - 離れた項目へ戻らずに、話の対象や指示語が指す内容を特定できるか。
- 全文を読む。
  - 文の断片化、推論の欠落、条件の後出しはないか。
  - 同じ内容を、不必要に繰り返していないか。
  - 原文や資料の意味を変えていないか。
  - 条件をまとめた箇所は、具体例でも同じ判断になるか。
- 見た目の区切りも、内容のつながりに合わせる。
  - 同じ話題の短い項目は、不要な空行で離さない。
  - 大きな話題の切り替わりは、空行や見出しで区切る。
  - 強調を増やす前に、位置と階層を直す。
- 出力には、依頼された本文だけを載せる。
  - 出典や判断に必要な不確実性は、本文の情報として残す。
  - 作業中のメモや点検結果は、求められた場合にだけ出す。

規則の根拠と適用限界は、[調査と設計判断](references/research.md)にまとめている。
