# 短文をつないだ階層的な箇条書きで説明する

- 本文は、短文を階層的に並べた箇条書きを基本にする
  - 要点は浅い階層に置き、理由・具体例・補足は説明する対象の下に置く
  - 理由や推論も短文でつなぎ、上から順に読めば説明をたどれる形にする
- 一つの項目は短く保つが、必要な説明は減らさない
  - 長い説明は、問いごとのまとまりに分けて残す
  - 文を断片にしてしまったり、長い段落に箇条書き記号を付けただけで済ませたりしない

## 1. 残す内容と置き場所を決める

- 読者の問いと、依頼された詳しさ・編集範囲を基準にする
  - 構成の変更を依頼されたからといって、情報を削ってよいとみなさない
  - 対象・事実・条件・確信度・発言者をそのまま保ち、資料にない理由や具体例を付け足さない
  - 架空の例か、実際の報告かという区別も保つ
- その箇所を理解するのに必要な答え・前提・理由・具体例は、その場に残す
  - 結論を左右する条件・例外・不確実性も、関係する説明と一緒に示す
- 長い箇所は、分割する前に内容と配置を見直す
  - 後で必要になる情報は、その説明の近くに移す
  - 独立して参照する証明や追加の例は、案内を残したうえで補足や付録に移せる
  - 本筋を理解するのに必要な説明は残し、参照先との往復を前提にしない
  - 削除が許されている場合は、読者の目的に役立たない情報を省く
- 役割のない繰り返しは一つにまとめる
  - 解説と早見表のように、別の読み方に役立つ再掲は残せる

## 2. 前提から理解できる順に並べる

- 読者がその場で理解できる答えなら、先に示してよい
  - 新しい概念を扱うときは、理解できる問いや設定から始める
  - 具体例が必要なときは、その例で何を調べたいのかにつなげる
  - 要点を浅い階層に置くことと、前提より先に書くことは分けて考える
- 読者にとって新しい用語や記号は、必要な説明を添えて使う
  - 何のための概念か分かりにくい場合は、必要になる場面を示す
  - 初めて使う箇所で短く説明できるなら、その場で説明してよい
  - 読者がすでに知っている用語まで、毎回定義し直さない
  - 未知の概念を、別の未知の概念との違いだけで説明しない
- 比較や計算は、対象・初期状態・使う規則を先に示してから進める
  - 比較では、共通の設定と変える箇所を区別する
  - 後の結果を見てから、設定や比較対象を逆算させる書き方にしない
- 推論は、どの前提から何を得たのかを追える形にする
  - 複数の前提から導く結論は、前提を並べた後ろか、それらをまとめる親項目に置く
  - 結論を最後の前提だけの子項目にせず、必要な途中の操作も言葉や式で示す

## 3. 読む単位に合わせて項目を作る

- 問いごとに要点と説明をまとめてから、項目に分ける
  - 元の文や改行の位置を、そのまま項目の区切りにしない
- 一つの項目には、一つの要点を短く書く
  - 主張・操作・理由は、助詞・述語・必要な接続を残した文として書く
  - 主体や対象が切り替わるときは明示する
  - 分類や場合分けは、短いラベルで示せる
  - ラベルを付けただけで、何がなぜ起こるかの説明を済ませない
- 別々に確認したい操作・条件・例が混ざっているなら分ける
  - 短い条件と動作など、一緒に読んだ方が分かりやすいものは一つの項目にまとめる
  - 分けたせいで同じ条件の繰り返しや文の断片が増える場合も、まとめ直す
- 必要であれば、一つの項目に複数の文を残せる
  - 一続きの推論のように、分けるとかえって読みにくい箇所は短い地の文でつなぐ
  - 別の話題や長い説明全体まで、一つの項目に詰め込まない
  - 文字数や画面での折り返し位置だけを理由に区切らない
- 内容に合う形式を使い分ける
  - 同じ観点での比較は、表にまとめられる。必要な理由や条件は近くで説明する
  - 引用・語り・コード・数式など、まとまりが必要な内容は無理に分割しない
  - 一、二文で済む短い応答は、そのままの形でよい

## 4. 親子関係と条件の範囲を確かめる

- 子項目は、説明する対象のすぐ下に置く
  - 理由・具体例・操作の効果が、親項目の何を説明しているのかを確かめる
  - 親項目に複数の動作が含まれるなら、どの動作についての説明なのか分かるようにする
  - 親の範囲から外れる話題は、その並びから外して別の項目や節に置く
- 親子の関係は、親と子を合わせて読めば分かる形にする
  - 親の「次の二条件」や、子の「〜ため」「例えば」で関係が伝わるなら、さらにラベルを重ねない
  - 役割を読み違えそうな箇所にだけ、「目的：」などを添える
  - ラベルのためだけに階層を一段増やさず、置き場所の誤りは名前だけで直そうとしない
- 子項目に何を並べるかは、親が示した問いと範囲で決める
  - 「二つの選択肢」の下には、その二つを置く
  - 一つの主張の下に理由と例を並べて置く場合は、役割の違いが伝わればよい
- 親項目の役割に合わせて、条件の示し方を決める
  - 主張を述べる親項目には、「平均」「一部」「未確認」など、成立する範囲や条件を残す
  - 「変更の条件」のようなラベルを親項目にする場合は、そこで何の説明を読めるかが伝わればよい
- 共通する条件は、関係するすべての項目に掛かる位置に置く
  - 親項目や見出しから適用範囲が分かるなら、子項目ごとに条件を繰り返さなくてよい
  - 長い条件を分けて書くなら、「次の二条件を両方」のように組み合わせ方を示す
  - 離れた位置にある項目の条件を、説明なしで引き継がせない
  - 危険を避けるための注意は、該当する操作より前に置く
- 次に進む工程と、一つの工程の内訳・効果を区別する
  - 独立した工程は、同じ階層で番号を振って順に示す
  - 一つの工程の内訳は、その工程の下に置ける
  - 操作によって起こる変化は、同じ項目の中か、その子項目に書ける
- 関係の表し方を言い換えても、元の意味を変えない
  - 根拠・原因・例を取り違えず、資料にない因果関係を付け足さない
  - 「すべて」「一つでも」が数える対象と、「ない」が否定する範囲を確かめる

## 5. 見出しと階層を整える

- 見出しには、その箇所で読める対象や問いを書く
  - 文書の題名は主題と範囲を示し、下位の見出しはその中の具体的な話題を示す
  - 見出しの階層は話題の包含関係で決め、結論・理由といった役割に固定しない
  - 見出しの直後に要点文を置くことを必須にせず、見出し・導入・親項目の重複を避ける
- 同じ階層に項目が五つほど続いたら、話題が混ざっていないか見直す
  - 五項目は上限ではなく、見直しを始める目安である
  - 空行やリストの区切りを挟んでいても、一続きの説明として見る
  - 項目が少なくても範囲がずれていれば直し、明確に並列な内容であれば五項目以上でも残す
- 読み分けるのに必要な階層の深さは使う
  - 階層を浅くするために、意味のある親子関係までなくさない
  - 同じ意味のラベルの繰り返しや、一文を完成させるためだけの階層は減らす
  - 長くて独立した説明は、小見出しなどで区切り直せる

## 6. 表現を整えて読み直す

- 新規作成は常体を基本とするが、既存原稿の文体や明示された指定があればそちらを優先する
  - 動詞で終える文・「である」・短いラベルを、内容に合わせて使い分ける
  - 箇条書き末尾の句点は省き、複数文からなる場合の途中の句点は残す
  - 引用・コード・数式の内側は、機械的に書き換えない
- 見出しと浅い項目を読む
  - 必要な説明を見つけられ、主張の条件を取り違えないか
- 親項目と、その子項目を合わせて読む
  - 何について、どの関係で説明しているのかが伝わるか
  - 読者に不要なラベルや階層をたどらせていないか
- 全文を順に読む
  - 想定する読者が、説明されていない前提を推測せずに例や推論を追えるか
  - 元の資料の意味と一致しており、本文・表・見出し・参照先が対応しているか

成果物には、依頼された本文と必要な出典を載せる。作業記録や自己評価は、求められた場合だけ別に示す。
