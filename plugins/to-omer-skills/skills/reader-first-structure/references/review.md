# 読みにくさの原因を確かめる

本文の読み直しは、SKILL本体の「見出しと浅い項目」「親と子」「全文」の三通りで行う。問題が見つかった箇所では、次の表を手掛かりにする。

| 気になる状態 | 確かめること | 修正の候補 |
|---|---|---|
| 子が何の説明か分からない | 親のどの対象・動作を説明しているか | 親項目や置き場所を直し、必要なら接続や短いラベルを補う |
| ラベルがあっても読みにくい | 名前と内容が一致するか | 不要なラベルを外すか、分類を変える |
| 一項目が長い | 今そこで読む必要があるか。別々に確認したい内容が混ざるか | 必要性と配置を見直してから、分割・統合を選ぶ |
| 短いのに流れが分からない | 助詞・述語・接続が残るか | 必要な言葉を補い、分けすぎた項目をまとめる |
| 計算や比較で止まる | 必要な設定・比較対象・途中の操作が説明されているか | 資料を確かめ、前提の位置や省略された説明を直す |
| 本文と表で条件が違って見える | 対象・限定・否定の範囲が同じか | 資料に照らして言い直し、必要なら具体例で確かめる |

- 親子関係は、親と子を合わせて読む
  - 共通条件を親から受け継げるなら、各項目を単独の文章に書き直す必要はない
  - 理由・例・条件などの役割が曖昧なら、親の案内か子の文で関係を示す
- 修正後は、関係する箇所まで読み直す
  - 本文を変えたら、対応する表・見出し・参照先も確かめる
  - 移動した場合は、移動元と移動先で、条件や指示語のつながりも確認する
  - 同じ原因で読みにくくなっている箇所が、ほかにも残っていないかを見る
- 構文やリンクの確認だけで、文章の確認を済ませない
  - 想定読者が、説明されていない前提を推測せずに読み進められるかを確かめる

## 参照資料

- [W3C WAI：Content Structure](https://www.w3.org/WAI/tutorials/page-structure/content/)
  - 内容に対応したリストの種類と、入れ子を考える指針
- [W3C：Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)
  - 情報の構造や関係を、適切な構造またはテキストで伝える原則
- [Google：Procedures](https://developers.google.com/style/procedures)
  - 工程・内訳・結果の説明を区別する参考
- [Google：Lists and tables](https://developers.google.com/tech-writing/one/lists-and-tables)
  - 列挙する内容と、比較の軸をそろえる参考

これらは、構造や執筆に関する一般的な指針として参照する。短文の階層箇条書きに最適な項目数や深さを実証する資料ではない。

本体の「五項目」は見直しを始める目安であり、認知上の限界や実験で得た最適値ではない。常体・句点省略も、この記法の表記方針であり、あらゆる読者への優位性を主張するものではない。
