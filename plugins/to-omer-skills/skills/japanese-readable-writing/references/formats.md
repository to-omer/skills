# 形式の使い分け

地の文、リスト、表、図、Markdown、HTMLを、情報同士の関係と読み方に合わせて使い分ける。

## 基本方針

形式は、見た目の変化ではなく、情報同士の関係に合わせて選ぶ。文章を箱、リスト、表へ移すだけでは読みやすくならない。

- 因果、対比、経緯、論証は地の文でつなぐ
- 独立して拾い読みできる並列項目はリストにする
- 実行順や優先順位に意味がある場合は番号付きリストにする
- 同じ軸で短い値を比較する場合は表にする
- 文章より短く正確に関係を示せる場合は図にする

## 地の文

地の文は、項目間の関係そのものを説明する場合に使う。

悪い例:

- 更新通知は非同期
- 通知は失敗することがある
- 古い値が返ることがある

改善例:

> 更新通知は非同期であるため、通知に失敗すると古い値が返ることがあります。

リストへ分解すると、因果関係が失われる場合がある。

## 箇条書き

箇条書きは、次の条件を満たす場合に使う。

- 項目が同じ種類である
- 各項目を独立して読める
- 順序を入れ替えても意味が大きく変わらない
- 読者が項目を拾い読みする価値がある

項目の文法形式、視点、分類基準をそろえる。句点の扱いは [自然な日本語](japanese-style.md) の「箇条書きの句点」に従う。

全項目にかかる条件は、リストの前へ置く。特定の項目だけにかかる条件や例外は、その項目の下へ置く。

## 番号付きリスト

番号に意味がある場合だけ使う。

- 手順の実行順
- 優先順位
- 後から番号で参照する項目
- 件数が重要な一覧

単なる並列項目へ番号を付けると、不要な順序を示してしまう。

## チェックリスト

作業や確認の状態を記録する場合に使う。説明文をチェックリストへ変えない。

チェック項目は、完了したか判断できる形にする。

悪い例:

- 読みやすさ

改善例:

- [ ] 見出しだけで文書の流れを追える

## 表

表は、行と列の交点に意味があり、複数の対象を同じ軸で比較できる場合に使う。

表へ向く情報:

- 数値
- 短い状態
- 同じ形式の日時
- 選択肢ごとの可否
- 条件と結果の組み合わせ

表へ向かない情報:

- 長い説明
- 項目ごとに比較軸が異なる内容
- 因果関係や経緯
- 一つのセルだけが極端に長い内容

セルが文章で埋まる場合は、見出しと段落へ戻す。条件が複雑な場合は、判断表として軸を明確にする。

## 図と画像

図を作る前に、次を一文で答える。

> この図は、読者のどの問いへ答えるか。

図を採用する条件:

- 要素間の位置、流れ、包含、対応を文章より短く示せる
- 本文と図の対応が明確である
- 図を読むための凡例や説明が、元の説明より複雑にならない
- 色を見分けられなくても、文字、記号、形で意味を区別できる

装飾画像、本文と同じ内容を繰り返す画像、根拠のない統計図は加えない。重要な情報を図だけに置かず、本文または代替テキストでも伝える。

## 注記と警告

本文の流れを中断してでも注意させる必要がある場合に使う。

- 警告: 誤ると安全、データ、権利などへ重大な影響がある
- 注意: 作業結果や判断に影響する条件がある
- 補足: 一部の読者だけが必要とする追加情報

すべての段落を囲みへ入れない。囲みが連続すると、どれが重要か分からなくなる。

## Markdown

Markdownでは、見た目ではなく意味上の役割を構文で表す。

- 文書の題名は最上位見出し
- 節と小節は階層に合う見出し
- 通常の説明は段落
- 並列項目は箇条書き
- 手順は番号付きリスト
- コードはコードフェンス
- 引用は引用ブロック
- 比較は必要な場合だけ表

見出しレベルを飛ばさない。太字、改行、字下げだけで階層を表さない。出力先が対応していない拡張構文は使わない。

原文の改行をそのまま段落へ変換しない。意味上のまとまりで段落を作る。

## HTML

HTMLへ変換する場合は、内容の構造と日本語を整え、`create-html-document` Skill の規則も適用する。

最低限、次を守る。

- 見出し、段落、リスト、表、リンク、ボタンを役割に合う要素で表す
- DOM の読み順を意味上の読み順に合わせる
- 色、位置、太字だけで重要な区別を表さない
- 画像には目的に合う代替テキストを付ける
- 表では行と列の関係を要素で示す
- リンクは移動、ボタンは操作に使う

CSS、JavaScript、外部ライブラリ、レスポンシブ表示、単一ファイル性、実ブラウザー確認は `create-html-document` の規則に従う。

## アクセシビリティ

出力形式にかかわらず、重要な情報を一つの感覚だけに依存させない。

- 色だけで状態を区別しない
- 画像だけに結論を置かない
- 見出し階層で文書構造を示す
- リンクの目的を、前後の文脈またはリンク文から分かるようにする
- 読み上げたときも、リストや表の関係が分かるようにする

## 形式選択の確認

最終的に、各形式について次を問う。

- この形式は、情報の関係を正しく表しているか
- 地の文より短く、または明確になったか
- 見た目を変えるためだけに追加していないか
- 削除した方が論理の流れを追いやすくならないか
- 狭い画面や読み上げでも意味を失わないか
