# 自然で分かりやすい日本語に直す

この文書では、文、語句、助詞、表記を整える。文を短くすることだけを目的にせず、読者が語句や文の関係を正しく読み取れる日本語にする。

## 自然さを判断する基準

自然な日本語には、少なくとも次の条件がある。

- 誰が何をするのか分かる。
- 動詞と目的語の組み合わせが、日本語として無理なく読める。
- 助詞が、語と語の関係を正しく示している。
- 修飾語が、どの語にかかるか一つに定まる。
- 文の前半と後半が、論理的にも文法的にも対応している。
- 用語、文体、表記が文書内でそろっている。
- 読者が知らない前提を、推測で補わなくてよい。

「文法上は誤りでない」だけでは不十分である。日本語で通常使われる言い回しかどうか、意味に合う動詞を選べているかも確認する。

## 主体、行為、対象を明確にする

指示、責任、判断に関わる文では、次の関係を明らかにする。

- 誰が行うか。
- 何を行うか。
- 何に対して行うか。
- どの条件で行うか。
- いつ完了したと判断するか。

担当者への指示であることが分かっている場合でも、次の文では主体が読み取れない。

弱い例:

> 申請内容を確認した後、添付された本人確認書類を削除してください。

改善例:

> 担当者は申請内容を確認した後、添付された本人確認書類を削除してください。

文脈から主体が明らかな場合は、毎回主語を書く必要はない。ただし、主体が切り替わる箇所や、責任の所在が重要な箇所では省略しない。

## 主語と述語を対応させる

長い文では、文頭の主語と文末の述語が合わなくなることがある。

不自然な例:

> この機能の目的は、利用者が誤ってデータを削除しないようにします。

改善例:

> この機能の目的は、利用者によるデータの誤削除を防ぐことです。

または:

> この機能は、利用者が誤ってデータを削除するのを防ぎます。

「Aは、Bすることを目的としています」のような形を使う場合も、主語と述語の対応を確認する。

## 動詞と目的語の組み合わせを確認する

英語の表現を語ごとに置き換えると、日本語では通常使わない組み合わせになりやすい。

| 不自然または分かりにくい表現 | 自然な表現の例 |
|---|---|
| 順序を崩さない | 順序を前後させない、順序を変えない |
| 強さを壊さない | 義務や推奨の度合いを変えない |
| 意味を壊さない | 意味を変えない、意味を損なわない |
| 情報を利用可能にする | 読者が情報を判断や行動に使えるようにする |
| 理解を提供する | 理解を助ける、理解できるように説明する |
| 判断を作る | 判断する、判断材料を示す |
| 構造を運ぶ | 構造を保つ、構造を引き継ぐ |
| 問題を表面化する | 問題を明らかにする、問題が明らかになる |
| 文章を消費する | 文章を読む、情報を確認する |

表の言い換えは文脈に応じて選ぶ。特定分野で定着している用語を、一般語へ機械的に置き換えない。

## 助詞を省きすぎない

見出しやメモでは助詞を省くことがあるが、本文で省きすぎると語の関係が分かりにくくなる。

### 「の」を補う

- `意味保存` → `意味の保存`
- `読者理解` → `読者の理解`
- `条件確認` → `条件の確認`
- `文章品質改善` → `文章の品質の改善` または `文章の品質を改善すること`

ただし、固有の専門用語や定着した複合語まで分解しない。

### 「を」「に」「が」を補う

- `設定変更する` → `設定を変更する`
- `利用者説明する` → `利用者に説明する`
- `担当者確認済み` → `担当者が確認済みである` または `担当者による確認が完了している`

助詞を補った結果、文が重くなる場合は、名詞の列を動詞中心の文へ組み直す。

## 名詞を重ねすぎない

名詞が続くと、語の関係を読み手が補わなければならない。

分かりにくい例:

> 顧客申請内容確認結果通知機能

改善例:

> 顧客の申請内容を確認し、結果を通知する機能

見出しや用語名として短い名詞句が必要な場合でも、本文では関係を説明する。

### 動作を名詞にしすぎない

- `確認を実施する` → `確認する`
- `設定の変更を行う` → `設定を変更する`
- `利用が可能です` → `利用できます`
- `判断を行います` → `判断します`
- `削除の実行をしてください` → `削除してください`

ただし、正式な業務名、手続き名、見出しとしての名詞は、そのまま使う場合がある。

## 修飾語を修飾先の近くに置く

長い修飾語が離れていると、どの語にかかるか分かりにくくなる。

曖昧な例:

> 担当者が確認した利用者の申請書を保管する場所

考えられる意味は複数ある。

- 担当者が確認した申請書を保管する場所
- 利用者が申請書を保管する場所を、担当者が確認した

原文から意味を一つに決められない場合は、推測で直さず、確認事項として示す。

修飾が長い場合は、次のいずれかで直す。

- 修飾語を修飾先の近くへ移す。
- 長い条件を文頭へ出す。
- 一文を二つに分ける。
- 名詞句を、主語と述語のある文にする。

## 一文に詰め込みすぎない

一文の長さだけで良否を決めない。次の兆候がある場合は、文を分けるか構文を組み直す。

- 主語と述語の組み合わせが複数ある。
- 条件がどの結論にかかるか分かりにくい。
- `が`、`ので`、`ため`、`し` で節が連続している。
- 列挙が文中に埋め込まれている。
- 括弧が重なっている。
- 文頭の話題と文末の結論が離れすぎている。

ただし、条件と結論の関係が強い場合は、無理に別文へ分けない。

悪い分割:

> ログを保存します。容量が減ります。削除できます。

改善例:

> ログを保存すると、空き容量が減ります。空き容量を増やす必要がある場合は、不要なログを削除できます。

## 条件と例外を明確にする

- 長い条件は、文頭に置く。
- 複数条件がある場合は、`かつ` と `または` を区別する。
- 条件の組み合わせが複雑な場合は、箇条書きや判断表を使う。
- 原則と例外を、離れた場所へ置かない。
- 例外の対象が一つの項目だけなら、その項目の下へ字下げする。

例:

```markdown
次の二つを両方満たす場合に申請できます。

- 契約開始から30日以内である。
- 管理者の承認を受けている。
```

「原則として」「必要に応じて」など、裁量を残す表現を具体化する場合は、制度上の意味を変えないようにする。基準が不明なら、勝手に期限や条件を作らない。

## 否定の範囲を明確にする

二重否定や長い否定文は、何を否定しているか分かりにくい。

分かりにくい例:

> 承認がない場合を除き、利用できないことはありません。

改善例:

> 承認を受ければ利用できます。

禁止事項を書く場合は、必要に応じて代わりの行動も示す。

> 個人のメールアドレスへ送信しないでください。社外へ共有する必要がある場合は、承認済みのファイル共有サービスを使用してください。

## 義務、推奨、予定、推測を区別する

書き換えによって、義務や許可の度合い、内容の確実さを変えない。

| 意味 | 表現例 |
|---|---|
| 義務 | 〜しなければなりません、〜する必要があります |
| 禁止 | 〜してはいけません、〜しないでください |
| 推奨 | 〜することを勧めます、〜するのが望ましいです |
| 許可 | 〜しても構いません |
| 可能 | 〜できます |
| 予定 | 〜する予定です |
| 推測 | 〜と考えられます、〜の可能性があります |
| 確定 | 〜です、〜します |

`してください` は、依頼、手順、義務のいずれにも使われる。規程や契約では、制度上の意味を確認してから言い換える。

## 指示語の参照先を一つにする

`これ`、`それ`、`この場合`、`当該`、`前者` などが複数の内容を指し得る場合は、具体的な名詞を繰り返す。

分かりにくい例:

> 申請書と本人確認書類を担当者へ提出してください。これを確認した後、削除します。

改善の方向:

> 担当者は申請書と本人確認書類を確認した後、本人確認書類を削除します。

何を削除するか原文から分からない場合は、確認事項として残す。

`上記`、`下記` は、表示順が変わる媒体や再利用される文章では避ける。節名、項目名、リンク文で参照する。

## 接続表現を使い分ける

文どうしの関係を誤読しやすい場合は、適切な接続表現を使う。

- 原因と結果: `そのため`、`したがって`、`〜ので`
- 条件: `〜の場合`、`〜のとき`
- 例外: `ただし`、`〜を除く`
- 対比: `一方`、`これに対して`、`しかし`
- 追加: `また`、`さらに`
- 例: `例えば`、`具体的には`
- 言い換え: `つまり`、`ここでいう〜とは`
- 時系列: `まず`、`次に`、`完了後`

`そして` や `また` だけで、原因、対比、例外の関係を表そうとしない。

接続表現を毎文入れる必要はない。文の順序だけで関係が明らかな場合は省く。

## 用語を統一する

同じ概念には、同じ呼び方を使う。

分かりにくい例:

> 利用者はワークスペースを作成できます。作成した作業領域にはメンバーを追加できます。このスペースは後から削除できます。

改善例:

> 利用者はワークスペースを作成できます。ワークスペースにはメンバーを追加できます。また、ワークスペースは後から削除できます。

技術文書では、単調さを避けるための言い換えより、対象を正確に指すことを優先する。

### 専門語

- 読者が知っている専門語は、必要以上に一般語へ置き換えない。
- 初心者に必要な専門語は、初出で短く説明する。
- 一般語にすると概念の範囲が変わる場合は、専門語を残す。
- 文脈で意味が分かる一般語まで定義しない。説明を増やすことで要点が埋もれないか確認する。

例:

> キャッシュ（再利用するために一時保存したデータ）を削除します。

### 略語

- 初出で正式名称を示す。
  - `サービスレベル目標（SLO）`
- 一度しか使わない略語は作らない。
- 複数の意味がある略語は、文脈だけに頼らない。
- 見出しだけに略語を置く場合は、近くで意味を確認できるようにする。

### 外来語

外来語を一律に避けない。次を確認する。

- 読者に通じるか。
- 製品や技術の正式名称か。
- 日本語に置き換えると意味が変わらないか。
- 短い説明を添えた方が分かりやすいか。

例:

- `アサインする` → `担当者を割り当てる`
- `ロールバック` → `以前の状態に戻す（ロールバック）`

## 抽象的な評価語を具体化する

次の語は、理由や判断基準がないと内容が伝わりにくい。

- 適切
- 十分
- 効果的
- 効率的
- 迅速
- 柔軟
- 直感的
- 包括的
- 高品質
- 最適

不十分な例:

> 問い合わせに適切に対応します。

改善の方向:

> 問い合わせ内容を確認し、担当部署へ引き継ぎます。

対応期限などの基準が確認できている場合は、その基準も書く。確認できない数値や期限は作らず、何が未確認かを示す。

## 直訳調や定型的な言い回しを見直す

次の表現は、内容が具体的であれば使える。しかし、説明の代わりに置かれている場合は削るか書き直す。

- `以下で見ていきます`
- `多角的に検討します`
- `単なるAではなくBです`
- `重要な役割を果たします`
- `価値を提供します`
- `〜を可能にします`
- `〜を通じて`
- `シームレスに`
- `包括的に`
- `〜という観点において`
- `〜することができます`

不十分な例:

> この機能は、効率的な情報共有を可能にします。

具体化:

> この機能を使うと、同じ文書を複数人で確認し、コメントを一か所にまとめられます。

`できます` をすべて削る必要はない。`利用できます` のように自然な可能表現として使われている場合は、そのままでよい。

## 丁寧さで要点を隠さない

対外文書では、簡潔な `です・ます` を基本にできる。

- 敬語を重ねて、主体と行動を曖昧にしない。
- 謝罪や謝意は必要な範囲で示し、重要事項より前に長く置かない。
- `させていただく` は、許可や恩恵の関係がある場合に限る。
- `ご確認のほどよろしくお願いいたします` だけで終えず、何をいつまでに確認するかを書く。

冗長な例:

> ご提出いただきますようお願い申し上げます。

簡潔な例:

> 4月10日までに提出してください。

相手との関係や組織の慣例に応じて、必要な丁寧さを調整する。

## 日付、時刻、数値、単位を具体的にする

- 運用情報では、`今日`、`近日中` より具体的な日付を使う。
- 時差が問題になる場合は、タイムゾーンを示す。
- 期間の開始と終了を明確にする。
- 営業日か暦日かを示す。
- 単位を省略しない。
- 上限、下限、概数、推定値を区別する。
- 税込、税別、手数料を含むかどうかを必要に応じて示す。

曖昧な例:

> 1〜3日で完了します。

改善例:

> 申請を受け付けてから、通常1〜3営業日で完了します。

原文にない基準は付け足さない。

## 句読点と括弧を整える

- 長い主語や条件節の後には、必要に応じて読点を置く。
- 読点の位置で意味が変わる文は、読点だけで直さず構文を組み直す。
- 括弧には補足を入れ、結論や重要な条件を入れない。
- 括弧の中にさらに括弧を重ねない。
- 長い中黒の並列は避け、`と`、`や`、リストを使う。
- 日本語の地の文では、装飾目的の全角ダッシュや引用符を多用しない。

## 表記をそろえる

文書内で次を統一する。

- `です・ます` と `だ・である`
- 漢字と仮名の使い分け
- 数字の全角と半角
- 日付と時刻の形式
- 句読点
- 製品名、機能名、UIラベル
- 英字の大文字と小文字

固有名詞、コード、コマンド、ファイル名、URL、識別子は、文章を整える目的で変更しない。

## やさしい日本語にする場合

日本語学習者などを対象にする場合は、通常の文章の改善に加えて次を行う。

- 伝える情報を絞る。
- 一文で扱う内容をさらに少なくする。
- 基本的で具体的な語を使う。
- 慣用句、比喩、省略語、難しい外来語を減らす。
- 受け身、使役、二重否定を減らす。
- 日時、場所、持ち物、行動を具体的にする。
- 必要な正式名称は、説明を付けて残す。
- 対象となる読者に実際に読んでもらい、必要な行動ができるか確認する。

難しい語を別の難しい語へ置き換えるだけでは改善にならない。

## 最後に通して読む

個々の文や語句を直した後は、文書を最初から通して読む。

次を確認する。

- 文ごとには正しくても、段落全体では同じ説明を繰り返していないか。
- 主体が途中で入れ替わっていないか。
- 前の文の情報を受けて、次の文が自然に続いているか。
- 助詞を補うべき複合語が残っていないか。
- 動詞と目的語の組み合わせが不自然ではないか。
- 名詞ばかりが続く文になっていないか。
- 直訳調の決まり文句が、具体的な内容の代わりになっていないか。
- 声に出して読んだとき、息継ぎの位置と文の区切りが合うか。
- 読者が、何を判断し、何を行うかを正しく理解できるか。
