# 読みやすさとレイアウト

内容と読者の利用状況に合わせて、本文幅、読み列、余白、見出し、目次、リスト、表、数式、図、対話機能、レスポンシブ表示を設計する。

## 読む仕事から設計する

ページの形は、内容と読者が行う仕事から決める。

- 最初から順に読む
- 必要な節を探す
- 複数の項目を比較する
- 手順を実行する
- 用語を検索する
- 印刷して参照する

一つのページで複数の仕事がある場合も、中心となる読み方を一つ決める。補助機能が本文より目立たないようにする。

## 主要な読み列

長文では、一つの主要な読み列を既定にする。本文が狭くなる固定サイドバー、常時表示の補助パネル、細かい複数カラムは避ける。

本文幅は、長い行で視線を失わず、短すぎる行で頻繁に折り返さない範囲にする。固定値を絶対条件にせず、フォントサイズ、文字種、内容に合わせる。

例:

```css
main {
  width: min(calc(100% - 2rem), 72rem);
  margin-inline: auto;
}

.prose {
  max-width: 46rem;
}
```

## タイポグラフィ

- 標準フォントでも本文を読めるフォールバックを用意する
- 極端に小さい文字を使わない
- 本文の行間は、複数行を追いやすい程度に取る
- 見出しは大きさだけでなく、余白と階層で区別する
- 太字、斜体、色を連続して使わない
- 長い英数字、URL、コードがレイアウトを壊さないようにする

Web フォントは、必要な文字を正しく表示するか、判読性を明確に高める場合に使える。見た目を少し変えるだけなら、実行時依存を増やさない。

日本語本文では、英語だけの本文より行間が必要になる場合がある。数値を固定の正解として扱わず、実表示で確認する。

## 余白とリズム

余白は、内容のまとまりを示すために使う。

- 同じ節内の段落間は近くする
- 新しい節の前は、段落間より広くする
- 見出しを、後続本文より前の内容へ近づけない
- 囲み、表、図の前後に、本文との境界が分かる余白を取る

すべての要素へ枠線や背景を付けず、通常の段落と余白を基準にする。

## 見出しと目次

見出しは、内容の階層を示す。見た目の大きさを得るために見出し要素を使わない。

目次は、長い文書で節間移動を明確に助ける場合に付ける。

- 項目数が少ない場合は付けない
- 本文幅を圧迫する固定サイドバーを既定にしない
- 中間幅では、本文上部または折り畳みへ移す
- 目次の文言は見出しと一致させる
- 現在位置を示す機能は、必要な場合だけ加える

## 地の文、リスト、表、カード

### 地の文

説明、因果、対比、経緯、論証は地の文を中心にする。

### リスト

独立して拾い読みできる並列項目へ使う。長い段落を単に分割するために使わない。

### 表

同じ軸で短い情報を比較する場合に使う。

- `caption` で表の目的を示す
- `th` と必要な `scope` で行列関係を示す
- 狭い画面では表のラッパーだけを横スクロールさせる
- セル内が長文になる場合は、表以外の形式を検討する

例:

```html
<div class="table-scroll" tabindex="0" aria-label="比較表。横にスクロールできます">
  <table>
    <caption>三つの選択肢の比較</caption>
    <!-- rows -->
  </table>
</div>
```

ラッパーへ `tabindex` を付ける場合は、実際にキーボード利用が必要か確認し、不要なフォーカス停止点を増やさない。

### カードとパネル

独立した対象を比較したり、操作単位を分けたりする場合に使う。連続した説明をカードへ分割すると、読む順序と関係が分かりにくくなる。

### 注記と警告

誤ると重大な影響がある情報、主流から外れるが必要な補足に使う。囲みを連続させず、重要度を視覚的に乱用しない。

## コード、数式、専門記号

コードは必要な範囲だけ載せ、長い行はコード領域内で横スクロールさせる。ページ全体を横スクロールさせない。

- 等幅フォントが利用できない場合も判読できるようにする
- コードの意味を本文で説明する
- コピー機能は、長いコードを頻繁に利用する場合だけ加える
- 行番号が必要でなければ付けない
- 記号だけで状態を表さず、ラベルを併用する

### 数式

短く単純な数式は、読みやすいテキスト、適切な Unicode 記号、MathML など、標準機能で明確に表せる方法を選ぶ。

数式が多い、分数・行列・添字・複雑な整列を含む、または組版の誤りが理解や正確さを損なう場合は、KaTeX や MathJax を CDN から利用してよい。単一 HTML であることだけを理由に、生の TeX や読みにくい代替表現へ落とさない。

外部の数式ライブラリを使う場合は、次を確認する。

- バージョンを固定する
- 必要な CSS と JavaScript だけを読み込む
- 利用できる場合は Subresource Integrity と `crossorigin` を設定する
- 読み込み前または失敗時にも、元の数式表現か説明文を読める
- 数式の意味を、周囲の本文だけでも把握できる
- 狭い画面で数式が本文全体をはみ出させない

オフライン動作が必須なら、資産を埋め込むか、外部ライブラリを使わない表現へ切り替える。

## 図と画像

図は、位置、流れ、包含、対応などを文章より短く表せる場合に使う。

- 本文から図を参照する
- キャプションで図の要点を示す
- 代替テキストは目的に合わせる
- 装飾画像は空の `alt` を使う
- 色だけで区別しない
- 小さい画面でも文字と凡例を読めるようにする
- 同じ主張を複数の図で繰り返さない

図が本文より複雑なら削除する。

## 色とコントラスト

配色は階層を補助するために使い、意味の唯一の手掛かりにしない。

- 状態には文字や記号を併用する
- 本文と背景のコントラストを確保する
- 薄い文字を長い本文へ使わない
- ダークモードを実装する場合は、両配色を確認する
- ユーザーの配色設定を尊重する場合は `prefers-color-scheme` を使える

テーマ切替は、必要性がなければ加えない。

## レスポンシブ表示

広い画面だけでなく、中間幅と狭い画面を確認する。

- 本文幅がサイド要素に圧迫されない
- 見出し、ラベル、ボタンが切れずに折り返す
- 表、コード、長い数式だけが必要に応じて局所的に横スクロールする
- 固定・sticky 要素が本文やフォーカス対象を覆わない
- タッチ操作の対象が密集しすぎない
- DOM 順序と見た目の順序が一致する
- 文字拡大やズームで内容が消えない

狭い画面へ収めるために、中心内容を非表示にしない。

## 対話機能

ネイティブ HTML を先に使う。

- 移動は通常のリンク
- 単純な開閉は、適する場合に `details` と `summary`
- レイアウトは CSS のメディアクエリ
- 表とコードはブラウザーのスクロール

JavaScript を使う場合も、初期 HTML に中心内容を含める。

検索や絞り込みでは、入力ラベル、結果件数、空結果、キーボード操作を確認する。タブでは、JavaScript が無効でも内容へ到達できる設計を優先する。

外部ライブラリは、独自実装よりアクセシビリティや操作の信頼性を明確に高める場合に使える。ただし、機能規模に比べて依存が大きすぎないか確認する。

## 印刷

印刷が要求される場合だけ、印刷用表示を必須確認にする。

- 操作専用のコントロールを印刷から除く
- 見出しと後続本文を不自然に分断しない
- 表、図、コード、数式の切れを確認する
- 背景色がなくても意味を失わない
- 必要な参照先を印刷後も識別できるようにする

印刷プレビューや出力を確認していない場合は、印刷確認済みと述べない。

## 固定テンプレートを避ける

安全な既定値は出発点であり、すべての文書を同じ見た目へする規則ではない。

- 読み物では、余白と本文を中心にする
- 比較文書では、表や定義リストを必要な箇所へ使う
- 数式の多い文書では、正確な組版と参照しやすさを優先する
- 用語集では、索引や検索が有効な場合がある
- 短い案内では、目次や多段階ナビゲーションは不要である

各部品について、削除すると読者の理解、探索、操作が具体的に悪化するかを確認する。悪化しない部品は加えない。
