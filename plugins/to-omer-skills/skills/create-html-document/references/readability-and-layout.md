# 読みやすさとレイアウト

文書の内容と用途に合わせて、HTML の構造、本文幅、余白、文字、ナビゲーション、表、数式、図、操作機能を設計する。

## 文書の用途を確認する

ページの構成は、読者が主に何をするかに合わせる。

- 最初から順に読む
- 必要な箇所を探す
- 複数の項目を比較する
- 手順を実行する

一つのページに複数の用途があっても、読者の主な利用方法を決める。

## 文書構造

完全な HTML 文書として、少なくとも次を含める。

- `<!doctype html>`
- 本文の言語を示す `html[lang]`
- `meta charset`
- `meta name="viewport"`
- 内容を表す `title`
- 主要内容を含む一つの `main`
- 文書の主題を示す一つの `h1`

見出しは元資料の階層に対応させ、レベルを飛ばさない。配置を CSS で変える場合も、DOM だけで自然に読める順序を保つ。

## 本文とナビゲーション

一般的な長文では本文を一列にし、固定サイドバーや常時表示の補助パネルで本文幅を狭めない。本文幅は文字種、フォントサイズ、内容に合わせ、実表示で調整する。

目次は、長い文書で節間の移動を明確に助ける場合に付ける。

- 項目数が少ない場合は付けない
- 目次の文言を見出しと一致させる
- ページ内リンクの参照先 ID を重複させない

## タイポグラフィと余白

- 極端に小さい文字を使わず、本文を追いやすい行間を取る
- 見出しを、大きさだけでなく余白と階層で区別する
- 太字、斜体、色を連続して使わない
- 長い英数字、URL、コードでレイアウトを崩さない

余白は内容のまとまりを示すために使う。すべての要素へ枠線や背景を付けず、通常の段落と余白を基準にする。

## 文書要素を HTML で表す

元資料の段落とリストの役割を保つ。連続した説明を、カードや短いリストへ分断しない。

元資料や内容設計に表がある場合は、行と列の関係を HTML の表として表す。

- `caption` で表の目的を示す
- `th` と `scope` で行列関係を示す

独立した対象や操作として示された内容は、見出し階層を保ってカードとして実装できる。警告、注意、補足は、重要度に合う要素とラベルで示す。

コードは原資料の範囲を保ち、役割に応じて `code` または `pre` と `code` で表す。

## 数式

TeX や LaTeX で記述された式は、KaTeX を基本として表示する。別の数式表現が指定されている場合や、原資料に MathML などの表現がある場合は、それを保つ。数式レンダラーを使う場合は、文書内の数式を同じ設定と書式で表示する。単なる数値、単位、変数名は数式として扱わず、`code`、`pre`、ユーザー入力例は自動レンダリングから除外する。

## 図と画像

図や画像は、内容との関係を保って配置する。

- 本文から図を参照する
- 図と説明を `figure` と `figcaption` でまとめる
- 代替テキストを図の目的に合わせる
- 装飾画像には空の `alt` を使う

## 配色とレスポンシブ表示

- 色を意味の唯一の手掛かりにしない
- 本文と背景のコントラストを確保する
- `@media (prefers-color-scheme: dark)` でダークモードに対応し、ライトモードとダークモードの両方で内容を読める配色にする
- 広い画面、中間幅、狭い画面で内容を読めるようにする
- 表、コード、長い数式は、ページ全体ではなく各要素内で横スクロールさせる
- 固定要素で本文や操作対象を覆わない
- 文字拡大やズームで内容や操作を失わせない

狭い画面へ収めるために、中心内容を非表示にしない。

## 操作機能

標準 HTML で実現できる操作を優先し、JavaScript を使う場合も主要な内容を初期 HTML に含める。

## 外部ライブラリ

KaTeX や構文強調などの外部ライブラリは CDN から利用できる。信頼できる配信元を使い、バージョンを固定して、使用する機能のファイルだけを読み込む。
