## 基準となる表示

デザインの指定がない場合は [document.css](../assets/document.css) を使い、[components.html](../assets/components.html) で部品の組み合わせ方を確認する。CSS は納品する HTML に含め、共通トークンで本文と部品の見た目をそろえる。

- 背景、本文、見出し、強調、補助文字、境界、アクセント、リンクには、用途別のトークンを使う
- 背景と本文は無彩色を基準にし、リンク・選択状態・図の要点には控えめな一色を共用する。基準 CSS では青系のアクセントを使っており、青みや暖かみの指定がある場合は同梱のパレットも使える
- 本文と見出しの階層は文字サイズと余白で表し、強調色はリンク、選択状態、意味のある区別に使う
- 文書ごとに必要なスタイルは基準 CSS の後ろに追加し、同じ役割の部品には同じ設定を使う

明暗の切り替え・印刷・タブの配置や操作条件は [ナビゲーションと文書操作](navigation-and-controls.md) を参照する。

## 文書の用途を確認する

ページの構成は、読者がその文書で主に何をするかに合わせる。

- 最初から順に読む
- 必要な箇所を探す
- 複数の項目を比較する
- 手順を実行する

一つのページに複数の用途がある場合でも、読者の主な使い方を決めておく。

## 文書構造

完全な HTML 文書として、少なくとも次の要素を含める。

- `<!doctype html>`
- 本文の言語を示す `html[lang]`
- `meta charset`
- `meta name="viewport"`
- 内容を表す `title`
- 主要な内容を収める一つの `main`
- 文書の主題を示す一つの `h1`

見出しは元資料の階層に対応させ、見出しレベルを飛ばさない。CSS で見た目の配置を変える場合でも、DOM の順序だけで自然に読めるように保つ。

## 本文とナビゲーション

一般的な長文では、一列の本文を基準にする。ナビゲーションを添える場合も本文に十分な幅を確保し、文字の種類・フォントサイズ・内容に合わせて実際の表示を見ながら調整する。

目次は節のあいだの移動を助ける場合に付け、文言を見出しとそろえる。参照先には一意の ID を付ける。独立した区分の表示方式は [タブを選ぶ条件](navigation-and-controls.md#タブを選ぶ条件) を参照する。

## タイポグラフィと余白

- 本文を目で追いやすい文字サイズと行間にする
- 見出しは文字の大きさだけでなく、余白と階層でも区別する
- 太字・斜体・色は、強調箇所を読み分けられる範囲で使う
- 長い英数字・URL・コードは、折り返しや局所的なスクロールで読めるようにする

余白は内容のまとまりを表すために使い、枠線や背景はまとまりの区別を助ける場合に加える。

## 文書要素を HTML で表す

元資料にある段落やリストの役割を保つ。連続した説明はつながりを保ち、独立した項目は用途に合う単位でまとめる。

項目同士の対応を示したり、正確な値を参照させたりするときは表を使い、行と列の関係を HTML で表す。

- `caption`、または直前の見出しを参照する `aria-labelledby` で表の目的を示す。同じ題名を二重に表示しない
- `th` と `scope` で行と列の関係を示す

補足には控えめな罫線、追加の説明には `details` を使い、独立した対象や操作は必要に応じて区切った領域で示す。警告・注意・補足は、それぞれの重要度に合った要素とラベルで示す。

元のコードはそのまま保ち、役割に応じて `code`、または `pre` と `code` の組み合わせで表す。説明用の例を補う場合は、本文の条件を反映させ、原資料からの引用と区別できるようにする。

## 数式

数式は KaTeX の HTML 出力に統一する。TeX / LaTeX に加え、MathML・Unicode・プレーンテキストで書かれた式も、意味を保ったまま KaTeX で扱える TeX 記法に整理する。出力設定、原式の保持、読み上げ名、未対応記法の扱いは [描画ライブラリ](renderers.md) に従う。

本文と数式で字面の大きさや行間、添字の読みやすさがそろうように、実際の表示を見ながら調整する。文書内では同じ設定を使い、`code`、`pre`、ユーザー入力の例は数式の自動レンダリング対象から外す。単なる数値や単位は、数式にせず通常の本文で表す。

盤面の値など、本文から独立して置く数式では、分数の分子や分母まで読める大きさを保つ。必要に応じて `\displaystyle` や式を表示する領域の文字サイズを調整し、括弧や上下の余白も確認する。本文中の式を一律に大きくしない。

## 可視化の選択

本文にある関係・変化・差を読み取れる表現を選ぶ。

推論を追いにくい箇所では、定義の対応や、計算・証明の途中で変化する対象を具体的に示す。描画ライブラリを選ぶことと、図で説明する内容を設計することの両方を行う。

| 内容 | 表現 |
| --- | --- |
| 数量の比較・推移・分布 | 棒、点、線などのグラフ |
| 条件分岐・状態変化 | フローチャート、状態遷移図 |
| 依存関係・階層 | 関係図、木構造 |
| アルゴリズムの進行 | 同じ配置で段階を進める図 |
| 入力値による結果の変化 | 入力に連動する図 |

元資料の数値・条件・因果関係をそのまま保ち、新しい測定値や比較結果を作らない。説明用の例や仮定を加える場合はその位置づけを示し、実測と計算・仮定を区別できるようにする。正確な値を参照したい用途には表を添える。

図の個数を目標にするのではなく、読み取りや操作によって何が分かるかを基準に選ぶ。主要な内容は、本文からも理解できるようにする。学習向けに段階を追って説明する場面では、図や操作でも答えを見せる順序を保つ。

## 図と画像

図や画像は、内容とのつながりを保って配置する。

- 本文の中から図を参照する
- 図と説明を `figure` と `figcaption` でまとめる
- 代替テキストはその図の目的に合わせる
- 装飾用の画像には空の `alt` を使う

図の中の文字は、本文と同じフォントを基本にする。フォントを部分的に収録する場合は、本文だけでなく、コード内の文字列やコメント、図、操作後に表示されるラベルまで対象に含める。コードの英数字は等幅を保ち、そのフォントに含まれない日本語などは本文用フォントでも補えるようにする。

グラフには軸・単位・必要な目盛りを付け、線や印の色は意味と対応させる。凡例の記号は SVG の図形や線、境界線、文字で表し、CSS の背景色だけに頼らない。背景を印刷しない設定であっても、系列との対応を読み取れるようにする。

幅の広い図を狭い画面に合わせて縮小したせいで、文字まで小さくならないようにする。配置の見直し、目盛りや注記の整理、必要に応じた局所的なスクロールによって、読める大きさを保つ。SVG の文字サイズは CSS の指定値だけでなく、`viewBox` で縮小された後の実際の大きさで判断する。

## 配色とレスポンシブ表示

- 色だけを、意味を伝える手掛かりにしない
- 本文と背景のコントラストを確保する
- 基準 CSS の `color-scheme` と `light-dark()` で OS の明暗設定に追従させる。独自の CSS では `prefers-color-scheme` も使える
- 数式、構文の色、差分、図のラベルと背景も、同じ表示モードに合わせる
- 広い画面・中間幅・狭い画面のいずれでも内容を読めるようにする
- 表、コード、長い数式は、ページ全体ではなく各要素の中で横スクロールさせる
- 固定配置の要素で、本文や操作対象を覆わない
- 文字の拡大やズームをしても、内容や操作が失われないようにする

基準 CSS のダークモードでは、暗い灰色の背景に落ち着いた明るさの本文を合わせ、見出しは少し明るくし、短い強調は太さと文字色で区別する。本文中の数式とインラインコードは、周囲の文字色にそろえる。

通常サイズの文字は実際の背景に対して 4.5:1 以上、基準 CSS の本文では 7:1 以上のコントラスト比を保つ。コントラスト比は読みやすさの下限にすぎないため、背景色が付く注釈・表・コードも含め、文字の多い画面で明るさを確認する。基準については [WCAG 2.2 の 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) と [1.4.6](https://www.w3.org/WAI/WCAG22/Understanding/contrast-enhanced.html) を参照する。

コードには文書と共通の背景面・基本文字色・アクセント色を使う。コードの構文、図の系列、差分の追加と削除など、意味の異なるものが見分けられる配色にする。

狭い画面でも、すべての内容にたどり着ける構造を保つ。印刷時は白地に濃い文字を基本とし、コードと図を読める状態で残す。補足の開閉と全タブの扱いは [印刷](navigation-and-controls.md#印刷) を参照する。

コマンドとその実行条件のように、離れると意味を取り違えやすい短いまとまりは同じページに収める。ただし、長い節や大きな図まで一括で改ページ禁止にして余白を増やすことは避け、必要な箇所だけをまとめる。図は印刷向けに配置を調整し、長い表はページをまたいでも見出し行を繰り返して読めるようにする。

## 説明とラベル

見出し・名称・配置・選択状態からそのまま伝わる内容は、重複する説明を省ける。判断基準は、その文を消しても読者の理解・判断・操作・参照が変わらないかどうかである。

本文の理由・条件・具体例、図表の単位・凡例・出典、操作名は必要に応じて残す。特定のラベルやレイアウト形式を一律に避けるのではなく、読者に役立つかどうかで選ぶ。意味が伝わりにくいアイコンには、短い可視ラベルを付ける。

## 操作機能

標準の HTML だけで実現できる操作を優先し、JavaScript を使う場合でも主要な内容は初期 HTML に含める。

ラベル付きの `button`・`input`・`select` を使い、現在の値や選択状態が分かるように表示する。キーボードで操作でき、ホバーしなくても読めるようにする。動的な結果には、必要に応じて `output` や `aria-live="polite"` を使う。動きを付ける場合は `prefers-reduced-motion` に従う。

テーマの切り替えと印刷は [アイコンボタン](navigation-and-controls.md#ヘッダーとアイコンボタン) の基準に従う。視覚的な重複を減らす場合でも、支援技術に伝える名前や状態は削除しない。

JavaScript が必要な操作欄は初期状態で `hidden` にし、初期化できてから表示する。ネイティブ HTML の操作はそのまま使う。図の探索が主目的の文書では、操作できない場合にも確認できる値や説明を用意する。
