## タブを選ぶ条件

文字数ではなく、読者がどの内容を一緒に読むかで決める。

| 読み方 | 基本の構成 |
| --- | --- |
| 定義から導出・証明・例まで順に進む | 一列の本文と、必要に応じた目次 |
| 条件や候補を見比べる | 並べて説明する構成、または比較表 |
| 必要な仕様・事例・資料群を独立して参照する | 少数の大分類に分けたタブと全文表示 |
| 一時的に詳細やヒントを確認する | 必要な箇所だけの `details` |

分類名は中身が分かる短い言葉にし、必要な前提は共通の導入または該当箇所で読めるようにする。区分が増えて選びにくい場合は、分類のしかたか表示方式を見直す。

## 全文表示と内容の保持

すべての区分を元の順序で初期 HTML に含め、一つの本文として表示を切り替える。JavaScript が初期化される前はすべての区分を表示し、分類リンクを通常のページ内リンクとして機能させる。JavaScript が必要なボタンは、初期化が済んでから表示する。

タブ列の近くに、内容の分類とは別に「全文表示」の切り替えを置く。全文表示中はすべての区分を連続して読めるようにし、分類リンクを目次として使えるようにする。この状態では、タブの役割と選択状態を外す。

## 移動とキーボード操作

タブ表示では WAI-ARIA APG のタブパターンに合わせる。

- タブ列に `role="tablist"` と名前を付け、各タブに `role="tab"`、`aria-controls`、`aria-selected` を付ける
- 各パネルに `role="tabpanel"` と `aria-labelledby` を付ける。パネル先頭の内容にフォーカスを当てられない場合は、パネル自体を `tabindex="0"` にする
- 選択中のタブだけを通常の Tab キー移動の対象にする。共通部品では左右キー・Home・End でフォーカスを移し、Enter・Space で選択を確定する
- 横向きのタブ列では上下キーの操作を奪わず、通常のスクロールを維持する。選択中の表示とフォーカス状態は、色だけに頼らず区別できるようにする

各区分とその中の見出しには安定した ID を付ける。URL のフラグメント、ページ内リンク、再読み込み、ブラウザーの戻る・進む操作のいずれからでも、対象の区分が表示されるようにする。閉じた `details` の中へ明示的に移動するときは、対象を囲む祖先の `details` だけを開いてから、フォーカスを当ててスクロールする。履歴は確定した移動の単位で残し、タブ列から切り替えたときはページの表示位置と入力値を保つ。

狭い画面でも、ラベルは読める大きさを保つ。横スクロールが必要な場合はタブ列の中だけに限定し、選択したタブが見える位置に収まるようにする。

各パネルの末尾には、隣の区分へ移る通常のページ内リンクを初期 HTML として含める。タブの順序と名前から `href` と表示名を決め、JavaScript での生成だけに頼らない。実際の移動には、共通 JavaScript のページ内リンク処理を使う。

- 左に「← 前の区分名」、右に「次の区分名 →」を表示し、存在しない側は省く。本文が短い場合も直後に置き、区分名が長いときは折り返す
- タブ表示で移動するときは、表示パネル・選択タブ・URL を同期させ、移動先の本文先頭にスクロールとフォーカスを移す。入力値は保つ
- 展開した `details` やコード全文の後に通常の文書フローで置き、全文表示や JavaScript 無効時でも章間のリンクとして使えるようにする。印刷時は非表示にする。前後リンクには、タブの役割や左右キー操作を付けない

静的なリンクの読み上げ名も、文書の言語で書く。

## 検索と互換性

共通部品では `hidden="until-found"` と `beforematch` を使い、ブラウザー内検索で見つかったパネルの表示とタブの選択を同期させる。通常の `hidden` や `display: none` では非表示の本文が検索対象にならないため、`until-found` を `display: none` で上書きしない。隠れたパネルの余白・枠・背景も取り除く。

機能検出で対応を確認できない環境では最初から全文表示にし、ブラウザー標準の検索を使う。対応環境でも、実際に検索が動くか確認する。この仕組みの対象はタブで隠している区分とし、まだ開いていない解答など別の目的で閉じた内容は、その状態を保つ。

## ヘッダーとアイコンボタン

通常は、短い題名と明暗の切り替え・印刷のアイコンを、冒頭の高さを抑えたヘッダーにまとめる。ヘッダーとタブ列は、本文と一緒にスクロールする通常の文書フローに置く。ページ内リンクの移動先には少し余白を確保する。固定表示や追従表示の指定がある場合は、本文とキーボードフォーカスを覆わないように調整する。

アイコンボタンは次を満たす。

- ネイティブの `button type="button"` を使い、`aria-label` または視覚的に隠したテキストで短い操作名を付ける。SVG は装飾として扱う
- ホバーとキーボードフォーカスの両方で操作名を確認できるようにし、`title` 属性だけに頼らない
- 操作領域は 44 CSS px 程度を目安にし、フォーカス状態が見えるようにする
- 「全文表示」のようにアイコンだけでは分かりにくい操作には、短い可視ラベルを残す

テーマの初期値は OS の明暗設定に合わせ、読者が手動で選んだ設定があればそちらを優先する。選択を保存できなくても、切り替えや他の機能は動くようにする。

共通部品では、テーマボタンに、次に切り替える先の操作名を表示する。`data-theme-label-light` と `data-theme-label-dark` には、それぞれのモードに切り替える操作名を文書の言語で指定する。この名前は `aria-label` とツールチップに反映されるため、`aria-pressed` は併用しない。

## 印刷

表示中のタブに関係なく、文書のすべての区分を元の順序で一度ずつ印刷する。操作用のヘッダー、タブ列、全文表示の切り替えといった画面向けの操作要素は印刷しない。

`@media print` でタブの非表示指定と高さ制限を解除し、白地に濃い文字で印刷できるようにする。ブラウザーの印刷メニューから印刷しても、同じ内容が出るようにする。

印刷時に展開する補足は `details[data-print="open"]` に限定し、まだ開いていない解答は閉じた状態を保つ。`beforeprint` / `afterprint` を使う場合は、印刷後に画面の選択タブ・テーマ・開閉状態を元に戻す。改ページを含む確認は [検証手順](validation.md) を参照する。

## 部品の組み込み

[components.html](../assets/components.html) は連続表示、[tabbed-document.html](../assets/tabbed-document.html) は独立した区分を切り替える文書の見本である。[document.css](../assets/document.css) と [document.js](../assets/document.js) を組み合わせて使う。

見本の文章、題名、区分数、識別子は、実際の文書に合わせて置き換える。採用した部品の CSS・JavaScript・アイコンは、納品する HTML にインライン化する。
