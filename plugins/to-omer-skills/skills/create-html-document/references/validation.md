# 検証

内容照合、ソース確認、依存関係、実表示、操作、最終通読を分けて確認する。

## 原則

Skill 本文の七段階レビューは常に実行する。各段階で指定された reference を開き、現在の成果物へ照合する。

ソースだけでは、視覚的な読みやすさ、レスポンシブ表示、操作性を確認できない。実ブラウザーだけでは、内容の欠落、意味の変化、依存関係の妥当性を確認できない。いずれか一つだけで完成と判断しない。

## 内部の実施記録

レビュー中は、次を内部で記録する。ユーザーが求めない限り、最終成果物には付けない。

| 段階 | 参照した節 | 実施方法 | 状態 | 修正内容または対象外の理由 |
|---|---|---|---|---|
| 1〜7 | 見出し名 | 内容比較 / ソース確認 / ブラウザー / キーボード / 通読 | 未確認 / 適合 / 修正済み / 対象外 | 短く記録 |

一つの段階で複数の節を照合する場合は、節ごとに行を分ける。該当要素がない場合も、ソースと要求を確認してから対象外とする。実施できなかった確認は、適合ではなく未確認として残す。

## 内容を照合する

元資料と HTML を比較し、次を確認する。

- 主題、結論、必要情報
- 数値、日時、単位
- 条件、例外、否定、確信度
- 引用、リンク、コード、数式
- 見出しの意味上の階層
- 元の言語

形式変換だけの依頼では、内容を要約、追加、再解釈していないか確認する。内容編集も行った場合は、該当する文章 Skill のレビュー結果と整合させる。

## ソースを確認する

ソースを先頭から読み、少なくとも次を確認する。

- 一つの完全な HTML 文書である
- doctype、言語、charset、viewport、title、main、h1 がある
- 見出し階層と DOM 順序が内容の読み順に合う
- ID が重複していない
- ページ内リンクの参照先が存在する
- リンク、ボタン、入力、表、画像が役割に合う要素と属性を持つ
- 外部ライブラリと外部資産が、依存関係の方針に合う
- 内部メモ、未完了の文言、秘密情報が残っていない

レイアウト上の妥当性は、[読みやすさとレイアウト](readability-and-layout.md) と実表示へ照合する。

## 実ブラウザーで確認する

利用可能なら、実際のファイルをローカルで開く。意図する公開・プレビュー環境がある場合は、そちらでも確認する。CDN を使う場合は、ネットワークが利用できる状態と、読み込みに失敗した状態の両方を確認できるとよい。

広い画面、中間幅、狭い画面を含める。目安として 1440、1024、768、390、320 CSS px 前後を使えるが、数値そのものを合格条件にせず、レイアウトが変化する境界と破綻し始める幅を確認する。

各幅で、[読みやすさとレイアウト](readability-and-layout.md) の次の節へ照合する。

- 「主要な読み列」
- 「タイポグラフィ」
- 「余白とリズム」
- 「見出しと目次」
- 成果物に存在する表、数式、図、コード、カードなどの節
- 「色とコントラスト」
- 「レスポンシブ表示」

ブラウザーを利用できない場合も第4段階と第7段階を省略しない。ソースと CSS を確認し、描画は未確認であると内部記録と報告へ明記する。

## キーボードと対話機能を確認する

対話機能がある場合は、実際にキーボードで操作し、次を確認する。

- 論理的な順序でフォーカスが移る
- フォーカス位置が見える
- コントロールの役割に合うキーで操作できる
- 入力やコントロールに分かる名前がある
- 状態変化と結果が必要に応じて伝わる
- フォーカスを失ったり、閉じ込めたりしない
- JavaScript が無効でも中心内容へ到達できる

対話機能がない場合も第5段階を省略しない。対話要素が存在しないことをソースで確認し、通常リンクがある場合はフォーカスと操作を確認する。リンクもない場合は、そのことを記録して対象外とする。

## 単一ファイル性と依存関係を確認する

単一ファイル性とオフライン自己完結性を別々に確認する。

### 単一ファイル性

ユーザーが複数ファイルを求めていない場合は、納品物が一つの `.html` であることを確認する。ページ固有の CSS、JavaScript、データ、簡単な画像やアイコンは、原則として HTML 内へ含める。

### 外部ライブラリと CDN

外部ライブラリがある場合は、次を確認する。

- 正確さ、読みやすさ、アクセシビリティ、表示または操作の信頼性を明確に高める
- 標準 HTML・CSS・小さな埋め込み JavaScript だけで同等の品質を得にくい
- 依存の規模が機能に見合う
- 信頼できる配信元を使い、バージョンを固定している
- 利用できる場合は Subresource Integrity と `crossorigin` を設定している
- 読み込みに失敗しても中心内容へ到達できる
- 依存先へ機密情報や個人情報を送らない
- 依存先、目的、オフライン時の影響を納品時に示す

KaTeX などによる数式組版は、複雑な数式の正確さと読みやすさを明確に高める場合に妥当な依存となる。単純な数式や短い装飾のためだけに導入しない。

### オフライン要件

オフライン動作、閉域環境、長期保存、厳格な Content Security Policy が必要な場合は、実行時の外部依存を残さない。必要資産を埋め込めない場合は、依存しない代替表現を使う。

通常の参考リンクや引用元へのリンクは、ページの実行時依存とは扱わない。

## 初見読者として通読する

ページを最初から読み、[読みやすさとレイアウト](readability-and-layout.md) の該当する全節へ照合する。日本語を編集した場合は、`japanese-readable-writing` Skill の初見読者レビューも実行する。

本文、見出し、目次、数式、図表、操作の間を移るたびに、読み順や関係を推測する必要がないかを見る。不要な機能や装飾が見つかった場合は削除し、影響するレビュー段階から再実行する。

## 修正後の再確認

修正した内容に応じて、影響する段階から第7段階までを再実行する。

- 内容を変えた場合は第1段階から
- DOM や見出しを変えた場合は第2段階から
- CSS や部品構成を変えた場合は第3段階から
- 画面幅ごとの配置を変えた場合は第4段階から
- 対話やアクセシビリティを変えた場合は第5段階から
- 埋め込み資産、CDN、外部ライブラリを変えた場合は第6段階から

再確認後に第7段階へ到達するまで、完成と扱わない。

## 実施結果を報告する場合

次を分けて書く。

- 対象ファイル
- 実際に使ったブラウザーや確認方法
- 確認した画面幅やモード
- 確認した外部依存とフォールバック
- 見つけて修正した問題
- 対象外と判断した要素と理由
- 実施できなかった確認

予定していた確認を、完了した確認として書かない。実ブラウザー、キーボード、支援技術、オフライン状態などを使っていない場合は、使用したと述べない。
