# HTML 文書の検証

原資料との照合に加え、ソースと実際の表示を確認し、機能の検証は実際に採用したものに絞る。

## 原資料と照合する

変換元の資料がある場合は、見出し・リンク・表・図・コード・数式・重要な数値を原資料と照合してから、本文を通読する。

内容の編集を伴う場合は、変更した箇所がユーザーの指定した範囲に収まっているかを確認する。

追加した図・コード例・操作については、数値・単位・尺度・条件・手順・状態が元資料と対応しているか照合する。例や仮定を実測のように示していないか、段階的に開示する内容を先に見せていないかも確認する。

## ソースを確認する

HTML パーサーやブラウザーの開発者ツールを使い、構文エラー、重複した `id`、リンク先の存在しないページ内リンク、CSS や JavaScript の誤った参照、仮データやデバッグ情報がないかを確認する。

文書構造は [文書構造](readability-and-layout.md#文書構造) を基準に確認する。SVG が複数ある場合や、明暗別の図を用意した場合でも、ID や内部参照が衝突しないことを確認する。

## ブラウザーで表示する

生成した HTML をブラウザーで開き、初期表示から処理が完了するまでの挙動を見る。コンソールやネットワークにエラーが出ていないかも確認する。

狭い幅・標準的な幅・広い幅と、文字を拡大した状態のそれぞれで、[読みやすさとレイアウト](readability-and-layout.md) と照合する。想定する画面幅の指定がない場合は、320〜390px、768px、1440px 程度を代表例にできる。

- ライトモード・ダークモードの両方で、本文・補助文字・コード・図について、文字と背景の見え方を実際に読んで確かめる
- 段落・短い強調・注釈・数式・コードが並ぶ画面で明るさと読み分けやすさを確認し、文字と実際の背景とのコントラストを測る
- ページ全体が横にはみ出さず、表・コード・数式の右端まで必要に応じて横スクロールできることを確認する
- 図を画面幅に合わせて縮めた結果、図の中の文字まで小さくなっていないかを測定と目視で確認する
- 実際の印刷結果を PDF などに書き出し、図・コード・数式・ページの区切り・白地の配色・補足の開閉を確認する

印刷は「背景グラフィックなし」の設定でも確認する。凡例の記号が消えていないか、コマンドと条件が別々のページに分かれていないか、大きな空白がないかを見る。画面上で印刷用 CSS を当てた表示だけでは、改ページの確認を済ませない。

## 採用した機能を確認する

操作機能は実際に動かして確認し、キーボードでも利用できることを確かめる。値を変更する機能については、初期値と代表的な変更に加え、その用途で問題になりうる境界条件も試す。

数式では、KaTeX による HTML 出力、元の TeX、読み上げ名、原式との意味の一致を確認する。MathJax や MathML、未処理の式、描画エラーが残っていないかも見る。代表的な式について、実際に使われているフォントや、分数・上付き・下付きの組み方も調べる。

コードと差分は元の文字列と照合し、構文の色、追加・削除の表示、行の対応が意図どおりかを確認する。差分については、行と語句の強調背景が重なる箇所も含め、構文の色や `+` / `-` のコントラストをライト・ダーク・印刷のそれぞれで確認する。日本語などを含む場合は実際の字形を見て、等幅の英数字とともに問題なく読めることを確認する。コピー機能がある場合は、元のコードだけがコピーされることを確かめる。

追加した実行可能な例は代表的な入力で実際に動かし、出力結果と本文の説明を照合する。未実行の場合は、その旨と確認できた範囲を納品時に伝える。

長いコードを含む `details` を開いたとき、コード枠の中に縦スクロールが出ず、ページ全体の縦スクロールで末尾まで読めることを確認する。狭い画面や文字を拡大した状態でも後続の本文や前後移動と重ならず、印刷時には途中で切れず全行が読めることも確認する。

外部ライブラリを使っている場合は、指定したバージョンが読み込まれ、初期化処理が正しい順序で実行されていることを確認する。

JavaScript を無効にした状態でも主要な本文・図・コード・数式が読め、動かない操作欄がそのまま残らないことを確認する。オフライン対応の指定がある場合は、外部通信を遮断した状態でも確認する。

### ナビゲーションと文書操作

採用した機能について、[操作条件](navigation-and-controls.md) と照合する。

| 機能 | 確かめる結果 |
| --- | --- |
| タブ | すべての区分と全文表示で欠落や重複がなく、キーボードでの選択とフォーカスが整合している。JavaScript 無効時は全文が表示され、通常のページ内リンクを使える |
| 末尾の前後移動 | 長い区分の末尾から隣の区分へ移動したとき、移動先の本文先頭とフォーカスが見える。先頭・末尾の区分、長短の区分、狭い画面のいずれでもリンクの方向と名前が正しい。JavaScript 無効時や全文表示でも通常のリンクとして移動でき、印刷では消える。初期 HTML と実際の表示の両方で確認する |
| 参照 | 非表示の区分への直リンク、ページ内リンク、再読み込み、戻る・進むのいずれでも目的の内容にたどり着ける。閉じた `details` の中を参照したときは、対象を囲む祖先の `details` だけが開く |
| 検索 | 非表示の区分にしかない語を、実際のブラウザー内検索で見つけられる。未対応の環境では全文表示で検索できる |
| ヘッダー・テーマ | ヘッダーが本文と一緒にスクロールし、狭い画面・高さの低い画面・拡大時にも操作できる。操作名を確認でき、設定を保存できなくても切り替えが動く |
| タブの印刷 | 先頭以外のタブとダークモードの状態から PDF を書き出したとき、すべての区分が一度ずつ含まれている。指定した補足だけが開き、画面用の操作要素は消え、印刷後は元の状態に戻る |

検索のテストは `beforematch` の手動発火だけで代用せず、未検証のブラウザーにまで結果を当てはめない。

## 最後に通読する

ページを最初から通して読み、主題や節同士の関係、本文と補助要素のつながりを自然に理解できるか確認する。

ラベルや説明の過不足は、[説明とラベル](readability-and-layout.md#説明とラベル) の基準で見直す。

最後に [Skill 本文の「成果物の境界」](../SKILL.md#成果物の境界) を確認する。修正を入れた場合は影響する箇所を再確認し、ページ全体をもう一度表示して確かめる。

検証は、内容や実際の利用上の問題を確かめるために行う。装飾の値や実装そのものを固定するだけのテストは追加しない。残っている具体的なリスクが解消したら、確認した範囲を納品メッセージで伝える。
